## ◆ ARQUITETURA DE SOFTWARE

Minha abordagem de organização de projetos prioriza separação de responsabilidades, baixo acoplamento e independência entre regras de negócio e infraestrutura.

```text
src/
│
├── API/
│   ├── Controllers/
│   ├── Middlewares/
│   ├── Configurations/
│   └── Extensions/
│
├── Application/
│   ├── Commands/
│   ├── Queries/
│   ├── Handlers/
│   ├── DTOs/
│   └── Validators/
│
├── Domain/
│   ├── Entities/
│   ├── ValueObjects/
│   ├── Aggregates/
│   ├── Events/
│   └── Interfaces/
│
└── Infrastructure/
    ├── Persistence/
    ├── Repositories/
    ├── Messaging/
    └── Services/
```

**Princípios fundamentais:**

- O domínio não depende de detalhes externos.
- A camada Application coordena os casos de uso.
- A API é responsável pela comunicação com os clientes.
- A Infrastructure implementa os detalhes técnicos.
- As dependências apontam para o núcleo da aplicação.
